Storytime account and session export bytes use `downloadStorytimeExportPackage`, authenticated by a current revocation-checked Firebase ID token. The URL carries an operation identity hash and a deadline, never a Storage signature or bridge credential. The browser checks the configured project's exact HTTPS Function endpoint before requesting its fresh token and uses private, redirect-blocked fetch. It checks the package SHA-256 before initiating a local download.

The authority is Storytime's own explicitly confirmed, server-owned `userId` privacy request and its immutable completion receipt. Confirmation expires after at most 24 hours; the package cannot outlive that request; individual download URLs expire after at most 15 minutes. Legacy packages lacking current confirmation, source inventory, expiry and completion authority require a fresh request. These controls do not claim canonical cross-system `uid` / `data.export` consent admission.

Packaging rereads the request, scoped source inventory and relevant deletion requests in the final transaction. Delivery repeats those reads before committing its audit and before every 64 KiB chunk, and repeats Firebase token revocation checks. Source drift, deleted or foreign parent sessions, request withdrawal, pending or completed relevant deletion, missing receipts, elapsed runtime and absolute expiry all deny further bytes. The object is pinned to its Storage generation and byte count. Earlier authorized bytes cannot be recalled after a later withdrawal.

The browser provides an explicit withdrawal control. Withdrawal revokes request delivery authority; object erasure remains governed by the existing destructive deletion/retention workflow. Direct client Storage access to `storytime-exports` remains denied by the existing rules.

Validation uses the actual request, packaging and HTTP handlers with synthetic Firebase/Storage dependencies and the actual browser client with a synthetic fetch transport. No real private contents, cloud download, grant enrollment, provider call, spending approval or production deployment is performed by those tests. Exact-head hosted CI and independently authorized runtime evidence remain prerequisites for release admission.

The narrator bridge uses Jobs `playback.delivery`, a nonsecret `urai-authenticated-private-media-v1` descriptor. Storytime's Firebase-token HTTP proxy `deliverStorytimeVoiceover` rereads its actual owner/session/script/consent receipt and relevant deletion requests, sends only the strict deliver body and existing server-only bridge credential to the configured Jobs bridge, commits its own audit before output, and checks current token/source/consent/deletion/deadline/secret before every 64 KiB browser chunk. Jobs separately binds canonical job authority and the Storage generation. Neither descriptor nor browser code receives a Jobs token or Storage signature. The adapter requires current browser account-epoch continuity before token retrieval, after retrieval and after the downloaded blob.

No mounted browser audio UI currently consumes the adapter. Voiceover remains explicitly hard-off in the product contract; this repair does not assert enabled narration, actual Jobs deployment parity, private audio access or provider runtime. Native source acceptance and the current paired Jobs runtime remain prerequisites.
