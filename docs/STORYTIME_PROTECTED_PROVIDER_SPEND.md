# Storytime provider spend admission

A late or lost persistence acknowledgement could confirm an atomically committed Storytime session and return it after the paid admission expired or its grants/source changed. This successor adds a final committed-output authority check after both normal acknowledgement and actual reconciliation. It retains the committed success and every financial hold while withholding output that can no longer be confirmed.

The earlier protected-provider donor routes the actual OpenAI leaf through canonical Factory v2 admission and keeps token-price observations separate from settled charges. This successor preserves that admitted source, its absolute-window correction and its original monotonic lifetime.

## Protected provisioning contract

Environment settings locate configuration and remain kill switches. They do not authorize a request. `STORYTIME_PRODUCTION_SPEND_URL` must be the canonical public HTTPS `/api/worker/production-spend` route and exactly match the genuine issuer's `gateway_url` in the protected owner/request binding. That protected locator pins the canonical deployment origin; changing an environment URL alone cannot redirect the worker token to a lookalike endpoint that fabricates admission without a shared-account hold. Provisioning must verify the genuine canonical deployment origin and pair it with its source receipts; the helper never creates or rotates that authority. `STORYTIME_SPEND_GATEWAY_SOURCE_SHA` identifies the actual paired Factory source. `URAI_SOURCE_SHA` must match this executor's actual clean, tracked Git HEAD and all three enforcement source paths. A runtime without verifiable Git provenance stays closed; a declaration cannot substitute for independently verified compiled/deployed source evidence.

The generation callable mounts the protected Firebase secret `STORYTIME_SPEND_WORKER_TOKENS_JSON`, whose object maps protected worker IDs to distinct worker tokens. The Factory registry must separately bind each token to executor repository `LifeLoggerAI/urai-storytime`, exact source, consumer `storytime-generation`, tenant digest, OpenAI API account and the actual credential digest. No product code creates these registrations, financial jobs, signatures, grants or account readbacks.

The server-owned processing claim records owner/request, the exact reviewed request SHA256, canonical provider-input SHA256 and explicit consent snapshot. The helper calculates:

* `source_input_sha256`: SHA256 of stable sorted JSON `{authority:{userId,requestId,reviewedRequestSha256},input:<actual provider input>}`.
* `semantic_input_sha256`: SHA256 of UTF-8 recursively sorted JSON parsed from the actual outgoing body. Array order, string values (including Unicode) and finite fractional values are retained. It excludes local owner/request/source/job labels and byte-only whitespace, key order and JSON escape differences.
* `request_sha256`: SHA256 of UTF-8 `POST\nhttps://api.openai.com/v1/chat/completions\n` followed by the exact frozen JSON body bytes.
* `credential_sha256`: SHA256 of stable sorted JSON of the actual normalized `authorization` header.
* `semantic_headers_sha256`: SHA256 of stable sorted JSON of the other normalized explicit headers, including content type.
* Tenant digest: SHA256 of the verified authenticated owner ID.
* Protected locator: SHA256 of stable sorted JSON `{user_id,request_id,reviewed_request_sha256,request_sha256,source_input_sha256}`.

Protected provisioning supplies `storytimePaidProviderBindings/<locator>` with `user_id`, `request_id`, `generation_request_id` (the existing `<owner>_<request>` processing claim), reviewed/source/request/semantic-input/credential/semantic-header digests, provider `openai`, executor/gateway SHAs, verified canonical `gateway_url`, `job_id`, `worker_id`, `account_id`, consent/rights receipt digests, nonempty `receipt`, `trusted_readback:true`, current complete ISO `observed_at`/`expires_at`, and no revocation.

`storytimeProviderConsentReceipts/<consent_receipt_sha256>` and `storytimeProviderRightsReceipts/<rights_receipt_sha256>` must be independently established server records whose whole stable sorted JSON hashes equal their IDs. Both bind owner/request/claim, reviewed/source digests, provider `openai`, purpose `storytime.generate`, current trusted readback, receipt identity and no revocation. Consent requires `status:GRANTED`, `story_generation:true`, `provider_processing:true`, and `consent_version:story-generation-consent-v1`. Rights requires `status:APPROVED` and `rights_reviewed:true`. Existing Firestore default-deny rules keep these new unmapped paths client-inaccessible. A caller checkbox, environment token or synthetic fixture cannot manufacture these protected proofs.

The approved Factory job must include all five source/request/semantic-input/consent/rights digests in its signed input list. Its v2 executor binds exact worker, tenant, repository/source, gateway repository/source, endpoint, model, credential, headers, actual normalized semantic input, content type, request size and asset `storytime/<tenant digest>/<request ID>/session`. Authentic independent deployment/control proofs, signed explicit bounded approval, actual account credential mapping, current global balance and fresh protected pricing are required by the canonical gateway before atomic admission.

The actual semantic-input digest must also match the protected Storytime binding, v2 executor/deployment/control binding, protected controls and pricing, and mandatory reserve echo. It is persisted in the unresolved spend observation and rechecked during final committed-output authority confirmation. Missing or inconsistent records reject; no legacy digest, approval or claim is inferred.

The canonical account transaction permanently owns `assetFactorySpendInputClaims` under provider/account/model/endpoint/semantic digest. Renaming a request/job, changing executor source or re-encoding identical JSON cannot reopen it. Preflight can reject an existing claim without another reservation or provider call. The claim survives unresolved output and settlement. This helper has no retry or reconciliation actor and cannot release the canonical or local daily holds.

The fresh signed budget rates additionally bind `input_usd_micros_per_million_tokens` and `output_usd_micros_per_million_tokens` to the configured observation rates. The canonical per-unit quote must cover the conservative token ceiling, the full protected cap must fit inside the local per-request ceiling, retries must be zero and runtime at most 20 seconds. The mandatory preflight `admission_expires_at` and reserve `reserved_at`/`admission_expires_at` fields are complete ISO timestamps. The client checks fresh approval and source authority, starts its conservative runtime before awaiting reserve, and uses the earliest preflight/proof/reservation/runtime expiration. A delayed reply cannot renew an approval or restart runtime. Missing, future, expired or expanded admission fields fail closed while any admitted hold stays reserved. The same absolute and monotonic output fences follow decoding, outcome recording, final authority reads and paid persistence reads/writes. A backward system-clock correction cannot extend the originally admitted elapsed runtime; neither clock is restarted after provider completion. Canonical account contention and independent final-charge reconciliation retain their existing authority.

## Final committed-output authority

The generation caller retains a second internal closure bound to the original admitted request. After normal persistence acknowledgement, or after the actual existing lost-ack reconciliation confirms persisted success, it requires that closure before returning paid output.

The final confirmation reads the current succeeded claim, original binding and protected consent/rights plus the persisted session in a Firestore transaction. The session must match the owner, request, reviewed input, provider and exact original job/account/attempt/request digest. It checks actual source before and after that awaited transaction, then checks both the original absolute and monotonic deadlines last. Source-check latency or a backward wall-clock adjustment cannot silently extend that lifetime. The original Storytime binding, consent and rights expiry minimum also narrows the existing canonical proof/runtime deadline.

If admission expires or grants/source change during acknowledgement, the callable returns unavailable. It preserves the already committed success and does not send another provider request, reopen admission or release money. Actual reconciliation confirms persistence facts; it does not renew output authority. Existing private-history, revision and privacy lifecycle policies remain under their current owner.

## Hold and outcome behavior

The exact request body and effective headers are frozen before admission and dispatched once, with redirects rejected. A credential environment change cannot replace the admitted credential. Coherent server authority and source fixity are rechecked before and after reservation and after decoding. One protected deadline covers response headers, body decoding and output safety checks. Missing, stale, cancelled, revoked, mismatched or unavailable evidence blocks output/dispatch at the applicable boundary.

Provider outcomes use only the gateway's `record` action and remain `RECONCILIATION_REQUIRED`; they never call `reconcile`. Lost reserve replies, provider failures, body timeouts, invalid reservation echoes and failed outcome observations never trigger resubmission or release money. The caller retains its entire local per-request ceiling in both global and owner daily counters, counts earlier unknown holds against new requests, and rejects malformed counters. A successful story can retain a usage observation while its charge remains unresolved.

Paid receipts have `actualCostUsd:null`, `observedCostUsd:<token price observation>`, `costStatus:priced_usage_observation`, `settlementStatus:RECONCILIATION_REQUIRED`, and an exact protected spend observation with `chargesReconciled:false`/`retryAuthorized:false`. Local deterministic builder receipts retain `NO_PROVIDER_SPEND`; provider admission failures never fall back to that builder. Uncertain generation requests retain the terminal `requires_reconciliation` retry barrier and tell the caller not to submit a replacement.

Paid story persistence carries an internal closure bound to the admitted request and original authority. Current claim, binding, consent and rights reads share a Firestore transaction with all story writes and the successful request transition. Grant revocation or late cancellation conflicts with that transaction; a retry repeats only the current authority read and staged story writes, never provider submission or spend admission. Source provenance and the absolute admitted expiration are checked before and after awaited authority reads and before those writes, and again after the transaction result. This is a client execution fence; real Firestore transaction/acknowledgement and provider/proxy hard runtime evidence remain required. The existing commit-acknowledgement reconciliation path still distinguishes an atomically persisted story from an unconfirmed output while retaining all financial holds. Reconciliation is followed by the same final committed-output authority confirmation as a normal acknowledgement. The deadline check immediately before writes and after acknowledgement follows source verification, so time spent verifying source cannot extend output lifetime.

Only a separately authenticated, independently signed final charge receipt can settle the canonical account. This donor does not add a local daily-hold release actor; local holds remain conservative until an independently governed reconciliation path can bind the genuine final canonical charge to the same owner/request/reservation. Old reservations or approvals are not automatically migrated, released or reopened.
